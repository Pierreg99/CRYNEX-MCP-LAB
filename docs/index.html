01 / Start here

From clone to first test.

The starter stays intentionally small: install from the lockfile, run the checks, then build the stdio server for your MCP host.

Quick start

Requires Node.js 22 or later and npm.

$ git clone https://github.com/Pierreg99/CRYNEX-MCP-LAB.git
$ cd CRYNEX-MCP-LAB
$ npm ci
$ npm run typecheck && npm test
$ npm run build

Connect / Desktop host

One process. An explicit path.

Build the server first, replace the absolute path below, and adapt this generic configuration to your host. Your host starts and manages the process.

Generic MCP host configuration

Replace /absolute/path with your checkout location.

{
  "mcpServers": {
    "crynex-mcp-lab": {
      "command": "node",
      "args": ["/absolute/path/to/CRYNEX-MCP-LAB/dist/src/index.js"]
    }
  }
}

          04 / Default boundaries
          
    Local by design.
    Small by default.
    
          
    The shipped examples process only the input they receive. Adding access to other systems is a deliberate project change, not a hidden side effect.
    
        
    
        
    
          
    ✓
    No network listener
    The server uses stdio; it does not open a port.
    
          
    ✓
    No arbitrary filesystem or child-process access
    The default tools do not access files or run shell commands; configured catalogs and tools are loaded only from explicit local operator paths.
    
          
    ✓
    No credentials in the starter
    The shipped tools do not require secrets or connect to third-party systems.
    
          
    ✓
    Keep protocol stdout clean
    Diagnostics go to stderr so MCP messages remain parseable.
